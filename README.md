# Альфа Хак - Новостная аналитика для крупного бизнеса

## Описание решения

Интеллектуальный сервис для руководителей крупного бизнеса, который определяет контекст компании, отбирает значимые для неё события и объясняет их влияние с учетом внешних источников и аналитики Альфа-Банка.

### Ключевые возможности

- **Персонализированный отбор новостей** — сопоставление информационных материалов с бизнес-контекстом компании
- **Агентная логика** — многошаговый процесс с планированием, работой с инструментами и самопроверкой
- **RAG-система** — семантический поиск по аналитическим материалам Альфа-Банка
- **Интерпретация событий** — объяснение влияния новостей на конкретный бизнес
- **Трассируемость** — полная история работы агентов с возможностью восстановления источников

### Режим работы

Сервис работает в двух режимах:

- **LLM-режим** — если задан `OPENCODE_API_URL` и доступен ключ, агенты используют
  разрешённые модели кейса (GLM-5.3-Flash / DeepSeek-V4.1-Flash).
- **Демо-режим (по умолчанию)** — если LLM недоступна, все ключевые шаги
  (ранжирование, интерпретация, верификация) выполняются локальными эвристиками.
  Сервис остаётся полностью работоспособным: собирает реальные новости, строит
  персональные интерпретации и показывает трассировку.

## Архитектура

### Агентная система

Реализована мультиагентная система с оркестратором:

1. **ClientProfileAgent** — анализ профиля клиента, определение бизнес-контекста
2. **NewsCollectorAgent** — сбор и классификация новостей из внешних источников
3. **RankingAgent** — ранжирование новостей по значимости для клиента
4. **InterpretationAgent** — генерация персонализированных интерпретаций
5. **VerificationAgent** — верификация качества и корректности результатов

### Технологический стек

- **Python 3.11** — основной язык разработки
- **FastAPI** — веб-фреймворк для API
- **GLM-5.3-Flash / DeepSeek-V4.1-Flash** — LLM модели (разрешены в рамках кейса)
- **Sentence Transformers** — для семантического поиска (RAG)
- **Docker** — контейнеризация

## Требования к окружению

- Python 3.11+
- Docker и Docker Compose (опционально)
- Доступ к OpenCode API — опционально, для LLM-режима

## Установка и запуск

### Локальный запуск

1. Клонируйте репозиторий:
```bash
git clone <repository-url>
cd solution
```

2. Создайте виртуальное окружение:
```bash
python -m venv venv
source venv/bin/activate  # Linux/Mac
# или
venv\Scripts\activate  # Windows
```

3. Установите зависимости:
```bash
pip install -r requirements.txt
```

4. Создайте файл `.env`:
```bash
cp .env.example .env
```

5. Запустите сервер:
```bash
uvicorn api.main:app --reload --host 0.0.0.0 --port 8000
```

### Запуск через Docker

```bash
docker-compose up --build
```

## Использование

### API Endpoints

- `GET /` — проверка состояния сервиса
- `POST /api/analyze` — запуск полного анализа для клиента
- `GET /api/clients` — список доступных клиентов
- `GET /api/analytics/search` — поиск по аналитике Альфа-Банка
- `GET /api/health` — проверка здоровья сервиса
- `GET /app` — веб-интерфейс

### Пример запроса

```bash
curl -X POST "http://localhost:8000/api/analyze" \
  -H "Content-Type: application/json" \
  -d '{"client_id": "CLIENT_001"}'
```

По умолчанию ответ компактный (без полных текстов) — это удобно для публикации
через туннель. Чтобы получить полные тексты новостей и OCR-аналитики:

```bash
curl -X POST "http://localhost:8000/api/analyze" \
  -H "Content-Type: application/json" \
  -d '{"client_id": "CLIENT_001", "full": true}'
```

### Данные

- `data/client_profiles/clients.csv` — синтетические профили клиентов (в репозитории).
- Реальные CSV кейса (`df_Uid_data_hack.csv` и др.) не входят в репозиторий
  из-за размера. Укажите путь к ним через переменную окружения:

```bash
export CLIENT_DATA_CSV=/path/to/df_Uid_data_hack.csv
```

Если файл не найден, сервис автоматически использует синтетические профили.
- `data/alfa_analytics/alfa_analytics.json` — OCR-тексты 9 аналитических
  материалов Альфа-Банка (в репозитории).

### Веб-интерфейс

Откройте http://localhost:8000/app в браузере.

### Публикация в интернете

```bash
./share.sh
```

Скрипт проверяет, что сервер отвечает, и поднимает временный туннель:
cloudflared → pinggy → localhost.run (первый рабочий вариант). В конце он
печатает публичную ссылку на веб-интерфейс (`/app`) и API (`/api/health`).
Можно выбрать провайдера явно:

```bash
TUNNEL=pinggy ./share.sh
```

Публичная ссылка живёт, пока запущен процесс туннеля. Бесплатные туннели
временные: pinggy — 60 минут, cloudflared/localhost.run — до перезапуска.
Pinggy при первом открытии в браузере показывает страницу-предупреждение,
нужно нажать «Continue».

## Парсер новостей

Парсер подключён к реальным внешним источникам и собирает живые новости:

**Источники** (конфигурация в `config/news_sources.json`):
- Коммерсантъ (`https://www.kommersant.ru/RSS/main.xml`)
- Ведомости (`https://www.vedomosti.ru/rss/news`)
- Интерфакс (`https://www.interfax.ru/rss.asp`)
- ТАСС (`https://tass.ru/rss/v2.xml`)

**Возможности**:
- `parse_rss` — парсинг RSS-лент с поддержкой редиректов
- `parse_api` — парсинг REST API
- `parse_html` — веб-скрейпинг с CSS-селекторами
- `collect_from_sources` — сбор из нескольких источников, дедупликация, фильтрация по дате
- Локальная классификация по ключевым словам (15+ категорий с весами)
- Фильтр бизнес-релевантности (отсеивает спорт, культуру, происшествия)
- Fallback на локальные демо-данные при недоступности сети

## Трассировка

Каждый шаг работы агентов фиксируется с входными и выходными данными:
- `input_data` — источники, признаки клиента, критерии релевантности
- `output_data` — результаты промежуточных этапов, использованные источники
- `error_message` — ошибки, если были
- `success` / `timestamp` — статус и время выполнения

Во вкладке «Трассировка» каждый шаг раскрывается и показывает полные данные —
можно восстановить, какие источники, признаки компании и промежуточные результаты
повлияли на итоговый вывод.
