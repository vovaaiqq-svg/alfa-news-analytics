# Альфа Бизнес — новостная аналитика для вашего бизнеса

Сервис для руководителей: собирает внешние новости и аналитику Альфа-Банка,
отбирает то, что важно именно вашей компании, и превращает события в понятные
**риски и возможности** с планом действий.

Интерфейс — в красно-белой стилистике «Альфа-Бизнес»: лендинг, вход,
регистрация в два шага, профиль компании, два отдельных агента, «Альфа-гид»
по карте сервиса, фильтры по источникам и темам, трассировка, аудит качества,
FAQ и обратная связь.

Новый визуал из интерактивного `/preview/` перенесён в основной `/app`:
плоский красный фон, белые карточки, кот-маскот, верхняя навигация и красная
карточка профиля. Рабочая логика, API и DOM-контракты SPA сохранены; стили
подключены отдельным `static/design.css` после базового `styles.css`, а
изображения лежат в `static/img/`.

## 🚀 Быстрый старт: открыть сайт за 4 команды

Нужен Linux/macOS (на Windows — WSL) и Python 3.11+.

```bash
git clone https://gitverse.ru/MisterKindly/alfa-news-analytics.git
cd alfa-news-analytics
chmod +x start.sh
./start.sh
```

Репозиторий публичный — клонируется без авторизации.

Скрипт сам:

1. создаст виртуальное окружение `.venv`;
2. установит лёгкие зависимости (без тяжёлого `torch`);
3. запустит сервер на `http://localhost:8000`;
4. поднимет публичный туннель и напечатает ссылку.

В конце в консоли будет примерно так:

```
==============================================
  ГОТОВО. Открой эту ссылку в браузере:

      https://что-то-там.lhr.life/app

  Локально:  http://localhost:8000/app
  Остановить: ./stop.sh
==============================================
```

Скопируйте ссылку и откройте её в браузере. Если появилась страница Pinggy
с кнопкой **Continue** — нажмите её.

Остановить сервер и туннель:

```bash
./stop.sh
```

> Ссылка живёт, пока запущен процесс туннеля. Бесплатные туннели временные:
> если ссылка перестала открываться — снова запустите `./start.sh`, адрес будет
> новый.

### Если публичный туннель не поднялся

В некоторых сетях Cloudflare недоступен. Явно выберите другой провайдер:

```bash
TUNNEL=pinggy ./start.sh
# или
TUNNEL=localhostrun ./start.sh
```

`start.sh` передаёт переменную `TUNNEL` в `share.sh`.

## 🔑 Демо-доступ

Откройте `/app`, нажмите **«Войти»**, затем **«Открыть демо-профиль»**
(или введите `demo` / `demo`).

Сразу откроется экран «Риски и возможности» для компании `U_84` — это главный
сценарий сервиса. Профиль компании доступен в верхнем меню. Для полноценных
LLM-ответов добавьте ключ в `.env` (см. раздел «LLM-режим»). Без ключа или
при недоступном API сервис остаётся работоспособным в локальном демо-режиме:
такие ответы явно помечаются и не выдаются за ответы модели.

Можно также зарегистрировать свою компанию: название юрлица, отрасль, регион,
масштаб, дополнительные характеристики, затем логин и пароль. Название
юрлица сверяется с внутренней базой, отрасль уточняется по ключевым словам,
а в профиле показывается число похожих компаний.

## ✅ Пошаговый сценарий проверки

1. Откройте `/app` → **«Войти»** → **«Открыть демо-профиль»**
   (или введите `demo` / `demo`).
2. Вы сразу попадаете на экран **«Риски и возможности»**: видны карточки,
   отобранные под профиль компании, и аналитика банка. Если свежих релевантных
   новостей нет, экран честно показывает пустое состояние, а не случайные материалы.
3. Переключите фильтр **«Только новости» / «Только аналитика банка»**,
   тему и сортировку. У каждой карточки есть блок «Позиция Альфа-Банка»,
   явная пометка режима разбора (AI или локальный) и кнопки вопросов.
4. Откройте **«Альфа-агент»**, спросите: «Что происходит с потребительским
   спросом?». В ответе будут источник, пометка режима и самопроверка.
5. Откройте **«Новостной агент»**, задайте вопрос по свежей теме. Если подходящих
   новостей нет, агент честно скажет об этом и предложит Альфа-агента — источники
   не смешиваются.
6. Перейдите в **«Трассировку»**: раскройте шаги, проверьте источники и блок
   **«Аудит качества»** (анализы, диалоги, самопроверка, отзывы).
7. Нажмите **«+ Компания»** в верхнем меню и зарегистрируйте компанию с отраслью
   «Другая сфера», например «Производство дронов и робототехники». Отрасль
   определится по ключевым словам, профиль дополнится характеристиками.
8. Отправьте отзыв в разделе **«Обратная связь»** — он появится в аудите.

Быстрая проверка API:

```bash
curl -s http://localhost:8000/api/health
curl -s -X POST http://localhost:8000/api/analyze \
  -H 'Content-Type: application/json' -d '{"client_id":"U_84"}'
curl -s -X POST http://localhost:8000/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"client_id":"U_84","agent":"news","question":"Что с потребительским спросом?"}'
curl -s http://localhost:8000/api/audit/summary
```

## 🧠 Как работает агентная система

Оркестратор последовательно запускает агентов и сохраняет промежуточные
результаты:

1. **ClientProfileAgent** — читает профиль компании, определяет отрасль,
   масштаб и бизнес-контекст.
2. **NewsCollectorAgent** — собирает внешние новости из RSS, классифицирует их
   и отсеивает спорт, культуру, происшествия и политику без делового угла.
3. **RankingAgent** — ранжирует новости по релевантности конкретной компании.
4. **InterpretationAgent** — объясняет влияние события: риски, что делать,
   возможности и как адаптироваться.
5. **VerificationAgent** — проверяет полноту и качество результата, при
   необходимости запускает адаптацию.

### Два отдельных агента в чате

- **Альфа-агент** отвечает только по OCR-материалам Альфа-Банка: макрообзоры,
  ставка ЦБ, инфляция, отраслевые отчёты. В ответе видны источники.
- **Новостной агент** отвечает только по внешним новостям, собранным из RSS.
  Он не использует аналитику банка.

Такое разделение не даёт смешивать источники и позволяет проверить, на чём
именно основан ответ.

### Трассировка

Каждый шаг содержит:

- `input_data` — источники, признаки клиента и критерии отбора;
- `output_data` — промежуточные результаты и использованные материалы;
- `sources` — ссылки на новости и файлы аналитики;
- `success`, `timestamp`, `error_message` — статус выполнения.

На экране «Трассировка» шаги раскрываются: можно восстановить, какие источники,
характеристики компании и промежуточные результаты повлияли на итоговый вывод.

## 📈 Аудит, метрики и обратная связь

### Что сохраняется

- `.run/audit.jsonl` — журнал действий AI-компонента: анализы, диалоги,
  режим ответа, число источников, задержка, результат самопроверки. Текст
  вопросов и секреты в журнал не пишутся.
- `.run/feedback.jsonl` — оценки, категории и текстовые отзывы.
- `GET /api/audit/summary` — сводка для экрана «Аудит качества»:
  число анализов и диалогов, средняя оценка, низкие оценки, доля LLM-ответов,
  pass rate самопроверки, последние отзывы и диалоги.
- В интерфейсе: «Трассировка» → блок «Аудит качества».

### Метрики

| Метрика | Зачем |
|---|---|
| Precision@5 отобранных событий | не тащим ли шум в топ карточек |
| Доля карточек с первоисточником | проверяемость выводов |
| Pass rate самопроверки | полнота, источники, использование профиля |
| Доля ответов с фактическими ошибками | качество интерпретации |
| Время ответа анализа и чата | UX и стоимость |
| Доля LLM / локального демо | устойчивость и стоимость |
| CSAT и доля низких оценок | обратная связь пользователей |
| Стоимость одного диалога | соблюдение дневного бюджета |

### Процесс

1. **Ежедневно** — смотреть низкие оценки и ошибки в аудите; помечать
   инциденты и источники, которые дали сбой.
2. **Еженедельно** — вручную проверять выборку карточек и ответов: есть ли
   первоисточник, не смешаны ли позиция банка и вывод модели/локальный разбор, сработала ли
   самопроверка.
3. **Ежемесячно** — обновлять набор эталонных вопросов, сравнивать модели и
   промпты, пересматривать ключевые слова отраслей и RSS-источники.
4. **По обратной связи** — если повторяются жалобы на тему, добавлять
   материал в аналитику банка или менять правила ранжирования; если падает
   pass rate, разбирать конкретные карточки, а не «крутить температуру».

### Бюджет LLM

Ключ один на команду, лимит — **500 ₽/день**. В прототипе стоимость
ограничивается архитектурно:

- интерпретации карточек считаются локально, без вызова LLM;
- в чат уходят только 2–3 отобранных фрагмента, а не весь корпус;
- `max_tokens=900`, ответы короткие;
- анализ кешируется на время сессии;
- при недоступности API включается локальный демо-режим с явной пометкой.

Формула для контроля:
`стоимость = input_tokens × price_in + output_tokens × price_out`.
Перед демонстрацией проверяйте фактический расход в кабинете провайдера;
ключ хранится только в `.env` и никогда не попадает в репозиторий.

## 🧩 Масштабирование

- **Новая отрасль.** При регистрации можно выбрать «Другая отрасль» и ввести
  свободное описание — `services/industry.py` сопоставит его с ОКВЭД по
  ключевым словам. Новые отрасли добавляются в реестр `INDUSTRIES` и в
  ключевые слова классификатора.
- **Новый тип клиента.** Профиль хранит юрлицо, масштаб, стадию, продукты,
  ВЭД и факторинг; для нового типа достаточно расширить схему профиля и
  правила `RankingAgent`, не меняя UI-каркас.
- **Новый источник.** RSS/API/HTML-адаптеры лежат в `parsers/news_parser.py`,
  список источников — в `config/news_sources.json`. Новый аналитический
  материал банка добавляется в `data/alfa_analytics/alfa_analytics.json`.
- **Новые клиенты.** Кнопка «+ Компания» в верхнем меню открывает
  регистрацию; профили и аккаунты уже разделены по `client_id`.
- **Production-путь.** `.run/` → PostgreSQL, фоновые задачи → очередь,
  секреты → vault, доступ → SSO и роли, наблюдаемость → логи/метрики/алерты.

## 🚪 Точка входа

В прототипе точка входа — лендинг `/app`: он выглядит как самостоятельный
сервис «Альфа-Бизнес» и сразу ведёт в рабочий сценарий. В продукте этот же
экран встраивается как заметная плитка/раздел на главном экране
«Альфа-Бизнес» с SSO и deep link на конкретную компанию. Это позволяет
переиспользовать текущий фронтенд без переписывания сценария.

### Preview нового визуала

Отдельный интерактивный preview макета доступен по адресу `/preview/`:
17 экранов, селектор экранов, стрелки `←`/`→`, режимы «Вписать» и
«100%», кликабельные пункты меню. Поля ввода, пароли, выпадающие списки,
текстовые области и основные кнопки работают локально: можно пройти
сценарий «лендинг → вход/регистрация → профиль → риски и возможности»,
открыть чат агента, задать вопрос и оставить отзыв. Это демо-слой поверх
макета: данные не отправляются в API и не сохраняются на сервере. Рабочее
приложение и все проверки остаются на `/app`; основной интерфейс уже
использует тот же визуальный язык, что и preview.

Что можно проверить в preview:

- вход с пустыми полями показывает ошибку, а с заполненными — сразу
  открывает риски и возможности;
- регистрация проходит шаги «бизнес → проверка → аккаунт → контакты →
  успех», поля сохраняются между экранами, пароль и e-mail валидируются;
- «Редактировать» в профиле открывает форму, а после «Далее» возвращает
  в профиль с обновлёнными данными;
- чат, вопрос и обратная связь принимают текст и очищают поле после
  отправки (ответы в демо-режиме не генерируются);
- подбор агента по вопросу ведёт в чат Альфа- или Новостного агента.

| `POST` | `/api/chat` | вопрос Альфа-агенту или Новостному агенту |
| `POST` | `/api/feedback` | отзыв о сервисе |
| `GET` | `/api/audit/summary` | метрики аудита и обратной связи |
| `GET` | `/api/analytics/search` | поиск по аналитике Альфа-Банка |
| `GET` | `/app` | веб-интерфейс |
| `GET` | `/preview/` | интерактивный preview нового визуала (17 экранов, локальные формы) |

### Пример анализа

```bash
curl -X POST "http://localhost:8000/api/analyze" \
  -H "Content-Type: application/json" \
  -d '{"client_id": "U_84"}'
```

По умолчанию ответ компактный — без полных текстов: `news_count` и 3
`news_items`, 1 `ranked_news`, 1 `analytics_insights`, до 3 `interpretations`
и 5 шагов `trace` с краткими формулировками. Чтобы получить полные тексты
новостей и OCR-аналитики:

```bash
curl -X POST "http://localhost:8000/api/analyze" \
  -H "Content-Type: application/json" \
  -d '{"client_id": "U_84", "full": true}'
```

## 🤖 LLM-режим

Штатный режим при доступном API — ответы через OpenAI-совместимый API
хакатона. Ключ и модель задаются только через `.env` (файл исключён из git), а не в коде и не во
фронтенде:

```bash
cp .env.example .env
# затем впишите LLM_API_KEY=sk-...
```

По умолчанию используются:

- base URL: `https://challenge.up.railway.app/v1`;
- модель: `deepseek/deepseek-v4.1-flash`;
- доступные альтернативы: `z-ai/glm-5.3-flash`, `qwen/qwen3.6-35b-a3b`,
  `qwen/qwen3-vl-30b-a3b-instruct`, `google/gemma-4-26b-a4b-it`,
  `moonshotai/kimi-k2.6`.

Если ключ не задан, модель не входит в разрешённый список или внешний API
недоступен, сервис переходит в локальный демо-режим. Скрытых альтернативных
провайдеров нет: API-ответы помечаются как `"mode": "llm"` только при реальном
ответе внешней модели, иначе — `"mode": "demo"`. Ключ никогда не логируется и
не возвращается в ответах.

Если организаторы выдали другой base URL, укажите его в `LLM_BASE_URL` в
`.env`; значение по умолчанию — `https://challenge.up.railway.app/v1`. На момент
сдачи этот адрес может быть недоступен: проверяйте `llm_status` в `/api/health`,
а демо-режим остаётся рабочим без ключа.

## 🛠 Ручной запуск

Первый терминал:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-lock.txt
python3 -m uvicorn api.main:app --host 0.0.0.0 --port 8000
```

Второй терминал:

```bash
./share.sh
```

`requirements-lock.txt` — зафиксированный набор лёгких зависимостей для
воспроизводимого запуска. `requirements-lite.txt` — тот же набор без жёстких
версий для экспериментов. Полный `requirements.txt` дополнительно ставит `sentence-transformers`
(семантический RAG, тянет ~2 ГБ `torch`); без него RAG автоматически работает
через поиск по ключевым словам.

### Docker

```bash
docker compose up --build
```

Сервис будет доступен на `http://localhost:8000/app`. `.env` и локальные данные
исключены из контекста сборки через `.dockerignore`; ключ передаётся в контейнер
только через переменные окружения `docker compose`. Сборка и запуск проверены
через `podman build` / `podman run`: `/app` и `/api/health` отвечают `200`, в
контейнере без ключа включается явный демо-режим.

## 🌐 Публикация в интернете

```bash
./share.sh
```

Скрипт проверяет, что сервер отвечает, и поднимает временный туннель:
cloudflared → pinggy → localhost.run (первый рабочий вариант). В конце он
печатает публичную ссылку на веб-интерфейс (`/app`) и API (`/api/health`).
Можно выбрать провайдера явно:

```bash
TUNNEL=pinggy ./share.sh
TUNNEL=localhostrun ./share.sh
```

Публичная ссылка живёт, пока запущен процесс туннеля. Бесплатные туннели
временные: pinggy — 60 минут, localhost.run — до перезапуска. Pinggy при первом
открытии показывает страницу-предупреждение, нужно нажать «Continue».

### Сторож туннеля

```bash
./keepalive.sh          # следит за ссылкой и перезапускает туннель
./keepalive.sh stop     # остановить
```

Текущий адрес хранится в `PUBLIC_URL.txt` (в корне проекта) и
`.run/cf_url.txt`. Лог — `.run/keepalive.log`.

## 🔒 Безопасность и ограничения демо

- Пароли демо-аккаунтов хранятся как PBKDF2-HMAC-SHA256 с солью.
- Секреты и `.env` не входят в репозиторий.
- `.run/` с аккаунтами, профилями и отзывами исключён из git.
- В LLM-режиме во внешний API передаются вопрос и подготовленные фрагменты
  новостей/аналитики; ключ хранится только в `.env`.
- Это прототип для хакатона: для production нужны внешняя БД, полноценная
  аутентификация с сессиями/токенами, rate limiting и аудит доступа.
